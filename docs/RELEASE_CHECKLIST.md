# Release Checklist

This checklist tracks mandatory pre-release tasks for launching Homeledger on Google Play. Each item is tagged with the responsible party: **(owner)** or **(engineer)**.

---

## 1. Google Play Console & Release Requirements

- [ ] (owner) **Privacy policy hosted at a public URL**: Host `docs/PRIVACY_POLICY.md` on a public webpage (e.g., GitHub Pages or website) and paste the public URL into Google Play Console under App Content > Privacy Policy.
- [ ] (engineer) **Privacy contact email replaced**: Update `kPrivacyContactEmail` in `lib/app/privacy_policy_text.dart` from `'REPLACE_BEFORE_RELEASE'` to the owner's actual contact email address.
- [ ] (owner) **ApplicationId finalized**: Verify `applicationId` in `android/app/build.gradle` is final (cannot be modified after the first APK/AAB is uploaded to Google Play).
- [ ] (owner) **App name and launcher icon finalized**: Ensure the public-facing app name "Homeledger" and launcher icons across all mipmap densities (and adaptive icon vectors) are final.
- [ ] (engineer) **versionCode and versionName**: Ensure `versionCode` (integer increment) and `versionName` (semantic version, e.g. `1.0.0`) are correctly set in `pubspec.yaml` / `android/app/build.gradle` for the release build.
- [ ] (owner) **Release signing key created and stored safely**: Generate release keystore (`key.jks`) using `keytool`, store safely in offline password manager, configure `key.properties` locally, and ensure the keystore file is NEVER committed to git.
- [ ] (engineer) **Target SDK meets current Play requirement**: Verify `targetSdkVersion` in `android/app/build.gradle` meets Google Play's current requirement (Target API 34+ / Android 14).
- [ ] (owner) **Data safety form answers**: Complete Play Console Data Safety section: declare that NO user data is collected, NO data is shared with third parties, all storage is on-device only, and CAMERA is used strictly for document scanning and work sample photography.
- [ ] (owner) **Content rating questionnaire**: Complete the IARC questionnaire in Play Console (utility / productivity tool, no objectionable content, no user-to-user interactions).
- [ ] (owner) **Store listing screenshots**: Capture phone and tablet screenshots showing Home, Progress, Time Log, Sample Gallery, and PDF Portfolio export.
- [ ] (owner) **Play Billing replacement notice**: Note that Google Play Billing currently uses `FakeEntitlementService` by owner decision; this MUST be replaced with real Google Play Billing (`in_app_purchase`) before charging users real money.
- [ ] (owner) **Test on real low-end phone**: Validate performance, scrolling, and memory usage on at least one low-end physical Android device (e.g. 2GB–3GB RAM).
- [ ] (engineer) **Test on Android 13 and 14 or newer**: Verify photo picker behavior, camera scanning, back navigation, notifications (none needed), and splash screen on Android 13 (API 33) and Android 14+ (API 34).
- [ ] (engineer) **Permission list from Fix C task 7 verified**: Confirm manifest merger contains only expected runtime permissions and that flagged transitive permissions are documented (see Section 2 below).

---

## 2. Permissions Found in Release APK (Fix C Task 7 Audit)

The release APK was built with `flutter build apk --release` and the merged manifest (`build/app/intermediates/merged_manifests/release/processReleaseManifest/AndroidManifest.xml`) along with the manifest merger blame log (`build/app/outputs/logs/manifest-merger-release-report.txt`) were inspected.

### Permissions List

| Permission | Status | Source / Dependency | Purpose & Notes |
| :--- | :--- | :--- | :--- |
| `android.permission.CAMERA` | Expected | `android/app/src/main/AndroidManifest.xml` | Used for capturing work samples and document scanning via camera. |
| `com.example.homeledger.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | Normal / System | `androidx.core:core:1.18.0` | Signature-level permission generated by AndroidX Core for secure internal broadcast receivers on Android 14+. |
| `android.permission.INTERNET` | **FLAGGED** | `com.google.android.datatransport:transport-backend-cct:2.3.3` (transitive dependency of `google_mlkit_document_scanner`) | **FLAGGED**: The app is designed to be an offline homeschool tracker. Note that while the debug build normally adds `android.permission.INTERNET` in `android/app/src/debug/AndroidManifest.xml` for Flutter hot reload and debugging (which is normal and expected in debug mode), the release APK merged manifest also contains `INTERNET` because it was introduced transitively by `google_mlkit_document_scanner` via Google DataTransport (`transport-backend-cct`). |
| `android.permission.ACCESS_NETWORK_STATE` | **FLAGGED** | `com.google.android.datatransport:transport-backend-cct:2.3.3` / `transport-runtime:2.2.6` (transitive dependency of `google_mlkit_document_scanner`) | **FLAGGED**: Introduced transitively by `google_mlkit_document_scanner` via Google DataTransport to monitor network connectivity before attempting diagnostic/telemetry transport. |

### Other Sensitive Permissions Check
- **Location permissions** (`ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`): **None found**.
- **Audio / Microphone permissions** (`RECORD_AUDIO`): **None found**.
- **Contacts permissions** (`READ_CONTACTS`, `WRITE_CONTACTS`): **None found**.
- **External Storage permissions** (`READ_EXTERNAL_STORAGE`, `WRITE_EXTERNAL_STORAGE`, `MANAGE_EXTERNAL_STORAGE`): **None found** (uses Android photo picker and app-private storage via `path_provider`).

### Summary
The only developer-declared runtime permission in `android/app/src/main/AndroidManifest.xml` is `CAMERA`.
However, `INTERNET` and `ACCESS_NETWORK_STATE` are pulled into the release build transitively by the Google ML Kit Document Scanner dependency (`com.google.android.datatransport:transport-backend-cct:2.3.3`). In debug builds, `INTERNET` is separately added by `android/app/src/debug/AndroidManifest.xml` for Flutter hot reload / debugging support, which is normal.
